# ADR-002: Proto Message Generation Extension

## Status

Proposed

## Context

After ADR-001, entdomain generates a pure Go domain layer and ent↔domain mapping methods. The next natural boundary is the **transport layer** — specifically gRPC, where protobuf messages must mirror the domain structs to avoid hand-written drift.

Existing tooling (`entprotobuf` from ent-contrib) generates proto messages directly from ent schema fields. It cannot be reused here for one critical reason: **virtual fields**. Virtual fields are declared only in entdomain annotations and are invisible to entprotobuf. Any proto messages generated by entprotobuf would silently omit virtual fields such as `FullName`, `IsPremium`, or `Amount`, breaking the domain ↔ proto contract.

Therefore entdomain must own the full proto generation pipeline — proto message files, field number stability, and domain↔proto mapping methods — so that virtual fields are first-class citizens throughout the entire stack.

---

## Decision

Extend entdomain with opt-in proto generation that:

1. Generates `.proto` message files from the domain struct definition (fields + virtual fields)
2. Maintains a JSON lock file for stable proto field numbers across regenerations
3. Generates `domain ↔ proto` mapping methods alongside the existing `ent ↔ domain` mappers

The proto generator is an **opt-in extension** — existing entdomain users are unaffected unless they configure it.

---

## Design

### Extension Configuration

Proto generation is enabled by passing `WithProto(...)` to `NewExtension`:

```go
entdomain.NewExtension(
    entdomain.WithPackagePath("internal/domain"),
    entdomain.WithPackageName("domain"),

    entdomain.WithProto(
        entdomain.WithProtoDir("proto"),           // output dir, relative to module root
        entdomain.WithProtoPackageName("entpb"),   // proto package name
        entdomain.WithProtoGoPackage("github.com/myorg/myrepo/proto/entpb;entpb"), // optional, auto-computed if omitted
        entdomain.WithProtoSplitFiles(),           // one file per entity; default: single ent_messages.proto
    ),
)
```

### Annotation API

#### Entity-level opt-in

```go
func (User) Annotations() []schema.Annotation {
    return []schema.Annotation{
        entdomain.Entity(
            entdomain.VirtualField("full_name",  entdomain.String),
            entdomain.VirtualField("is_premium", entdomain.Bool),

            // GoType with well-known auto-mapping
            entdomain.VirtualField("expires_at", entdomain.GoType("time", "Time")),

            // GoType with explicit proto type + import
            entdomain.VirtualField("amount",
                entdomain.GoType("github.com/shopspring/decimal", "Decimal"),
                entdomain.ProtoType("google.type.Money", "google/type/money.proto"),
            ),

            // GoType with no ProtoType — excluded from .proto output silently
            entdomain.VirtualField("internal", entdomain.GoType("myorg/types", "InternalState")),
        ),
    }
}
```

#### Field-level opt-out

Regular ent fields and edges are included in proto output by default. Use `entdomain.Field(entdomain.SkipProto())` to exclude:

```go
func (User) Fields() []ent.Field {
    return []ent.Field{
        field.String("name"),
        field.String("password_hash").
            Annotations(entdomain.Field(entdomain.SkipProto())),
        field.Bool("internal_flag").
            Annotations(entdomain.Field(entdomain.SkipProto())),
    }
}

func (User) Edges() []ent.Edge {
    return []ent.Edge{
        edge.To("posts", Post.Type).
            Annotations(entdomain.Edge(entdomain.IDs())),
        edge.To("audit_logs", AuditLog.Type).
            Annotations(
                entdomain.Edge(entdomain.IDs()),
                entdomain.Field(entdomain.SkipProto()),
            ),
    }
}
```

#### `FieldAnnotation` (new type)

```go
type FieldAnnotation struct {
    SkipProto bool
}

type fieldOption func(*FieldAnnotation)

func Field(opts ...fieldOption) FieldAnnotation
func SkipProto() fieldOption
```

#### `ProtoType` on virtual fields

```go
// ProtoType specifies the proto type for a GoType virtual field.
// typeName is the fully-qualified proto type (scalar or message).
// importPath is the optional .proto import required for the type; omit for scalars.
func ProtoType(typeName string, importPath ...string) virtualFieldOption
```

Stored in `VirtualFieldConfig`:

```go
type ProtoTypeConfig struct {
    TypeName   string // "string", "google.protobuf.Timestamp", "google.type.Money"
    ImportPath string // "", "google/protobuf/timestamp.proto", "google/type/money.proto"
}

type VirtualFieldConfig struct {
    Name      string
    FieldType FieldType
    ProtoType *ProtoTypeConfig // nil = auto-map if possible, else exclude
}
```

### Proto Type Resolution

Resolution order per field:

1. `SkipProto()` annotated → **excluded**
2. Virtual `GoType` with `ProtoType(...)` → use specified type + import
3. Virtual `GoType` matching a well-known mapping → auto-mapped
4. Virtual `GoType` with no match → **excluded** (silently)
5. Virtual primitive (`String`, `Bool`, `Int`, `Float64`) → auto-mapped
6. Regular ent field → auto-mapped from ent type

#### Built-in Auto-Mapping Table

| Go / entdomain type | Proto type | Import |
|---|---|---|
| `entdomain.String` | `string` | — |
| `entdomain.Bool` | `bool` | — |
| `entdomain.Int` | `int64` | — |
| `entdomain.Float64` | `double` | — |
| `GoType("time", "Time")` | `google.protobuf.Timestamp` | `google/protobuf/timestamp.proto` |
| `GoType("time", "Duration")` | `google.protobuf.Duration` | `google/protobuf/duration.proto` |
| `GoType("github.com/google/uuid", "UUID")` | `string` | — |
| Ent `field.Time(...)` | `google.protobuf.Timestamp` | `google/protobuf/timestamp.proto` |
| Ent `field.UUID(...)` | `string` | — |
| Ent `field.Bool(...)` | `bool` | — |
| Ent `field.String(...)` | `string` | — |
| Ent `field.Int(...)` | `int64` | — |
| Ent `field.Float(...)` | `double` | — |
| Ent `field.Enum(...)` | top-level enum | — |
| Ent `field.JSON(...)` | **excluded** | — |
| Ent `field.Other(...)` | **excluded** | — |
| Unknown `GoType(...)` | **excluded** | — |

Well-known mappings are registered in a table and extended over time without API changes.

### Output Structure

```
proto/entpb/                         ← configurable via WithProtoDir + WithProtoPackageName
  .entdomain.lock.json               ← field number registry, MUST be committed to source control
  ent_messages.proto                 ← generated (default: single file)

  # or with WithProtoSplitFiles():
  user_messages.proto
  post_messages.proto

internal/domain/
  user_gen.go                        ← existing: pure Go domain struct
  post_gen.go

  pbmap/                             ← new: domain ↔ proto glue layer (package pbmap)
    user_proto_gen.go                ← mapping functions for User
    post_proto_gen.go                ← mapping functions for Post
    proto_helpers_gen.go             ← shared conversion helpers (ToInt64Slice, etc.)
```

`pbmap` is a separate package that imports both the domain package and the proto package, keeping each side free of the other's dependency. Use `WithProtoHelpersInDomain()` to place mappers flat in the domain package instead (legacy mode).

### Field Number Stability (Lock File)

Field numbers in proto must be stable across regenerations for wire compatibility. The generator maintains a JSON lock file at `{protoDir}/{pkgName}/.entdomain.lock.json`.

```json
{
  "version": 1,
  "entities": {
    "User": {
      "fields": {
        "id":         1,
        "name":       2,
        "bio":        3,
        "status":     4,
        "created_at": 5,
        "full_name":  6,
        "is_premium": 7,
        "post_ids":   8
      },
      "reserved": [3]
    }
  }
}
```

**Allocation rules:**
- `id` field: always field number `1`
- New fields: `max(allocated ∪ reserved) + 1`
- Removed fields: moved to `reserved` — their numbers are never reused
- Explicit pin via `ProtoType` annotation overrides auto-allocation

The lock file must be committed to source control and reviewed in code review, similar to database migration files.

### Generated Proto File (`proto/entpb/ent_messages.proto`)

```protobuf
// Code generated by entdomain. DO NOT EDIT.

syntax = "proto3";

package entpb;

option go_package = "github.com/myorg/myrepo/proto/entpb;entpb";

import "google/protobuf/timestamp.proto";

enum UserStatus {
  USER_STATUS_UNSPECIFIED = 0;
  USER_STATUS_ACTIVE      = 1;
  USER_STATUS_INACTIVE    = 2;
}

message User {
  int64                     id         = 1;
  string                    name       = 2;
  optional string           bio        = 3;  // Optional() field
  UserStatus                status     = 4;
  google.protobuf.Timestamp created_at = 5;
  string                    full_name  = 6;  // virtual field: entdomain.String
  bool                      is_premium = 7;  // virtual field: entdomain.Bool
  repeated int64            post_ids   = 8;  // IDs edge
}
```

### Generated Domain↔Proto Mappers (`internal/domain/pbmap/user_proto_gen.go`)

```go
// Code generated by entdomain, DO NOT EDIT.

package pbmap

import (
    domain "github.com/myorg/myrepo/internal/domain"
    entpb  "github.com/myorg/myrepo/proto/entpb"
    "google.golang.org/protobuf/types/known/timestamppb"
)

func userStatusToProto(s domain.UserStatus) entpb.UserStatus { ... }
func userStatusFromProto(s entpb.UserStatus) domain.UserStatus { ... }

// UserToProto converts *domain.User to *entpb.User.
func UserToProto(d *domain.User) *entpb.User {
    if d == nil {
        return nil
    }
    return &entpb.User{
        Id:        int64(d.ID),
        Name:      d.Name,
        Bio:       d.Bio,                                  // *string → optional string
        Status:    userStatusToProto(d.Status),            // switch-based enum helper
        CreatedAt: timestamppb.New(d.CreatedAt),
        FullName:  d.FullName,                             // virtual field
        IsPremium: d.IsPremium,                            // virtual field
        PostIds:   ToInt64Slice(d.PostIDs),                // exported helper
    }
}

// UserFromProto converts *entpb.User to *domain.User.
func UserFromProto(p *entpb.User) *domain.User {
    if p == nil {
        return nil
    }
    return &domain.User{
        ID:        int(p.Id),
        Name:      p.Name,
        Bio:       p.Bio,                                  // optional string → *string
        Status:    userStatusFromProto(p.Status),
        CreatedAt: p.CreatedAt.AsTime(),
        FullName:  p.FullName,                             // virtual field
        IsPremium: p.IsPremium,                            // virtual field
        PostIDs:   FromInt64Slice(p.PostIds),              // exported helper
    }
}

// UserListToProto converts domain.UserList to []*entpb.User.
func UserListToProto(ds domain.UserList) []*entpb.User {
    out := make([]*entpb.User, len(ds))
    for i, d := range ds {
        out[i] = UserToProto(d)
    }
    return out
}

// UserListFromProto converts []*entpb.User to domain.UserList.
func UserListFromProto(ps []*entpb.User) domain.UserList {
    out := make(domain.UserList, len(ps))
    for i, p := range ps {
        out[i] = UserFromProto(p)
    }
    return out
}
```

### Enum Mapping

Enum types are re-declared at the top level in the proto file, following the `ENTITY_FIELD_VALUE` screaming snake case convention. A zero/unspecified sentinel is always emitted as value `0` per proto3 convention.

```protobuf
enum UserStatus {
  USER_STATUS_UNSPECIFIED = 0;
  USER_STATUS_ACTIVE      = 1;
  USER_STATUS_INACTIVE    = 2;
}
```

Domain ↔ proto enum mapping uses a generated switch-based helper (unexported, local to the pbmap package):

```go
func userStatusToProto(s domain.UserStatus) entpb.UserStatus {
    switch s {
    case domain.UserStatusActive:
        return entpb.UserStatus_USER_STATUS_ACTIVE
    case domain.UserStatusInactive:
        return entpb.UserStatus_USER_STATUS_INACTIVE
    default:
        return entpb.UserStatus_USER_STATUS_UNSPECIFIED
    }
}
```

The inverse `userStatusFromProto` is generated symmetrically. Direct casting is avoided because domain and proto enum types have distinct underlying types even when values match.

### Proto3 `optional` and Field Presence

Proto3 `optional` is used for any field that is a pointer in the domain struct. This restores field presence — the generated Go proto type also becomes a pointer, so the mapper passes values through without conversion for most types.

| Domain field | Proto declaration | Notes |
|---|---|---|
| `Name string` | `string name = N` | non-optional |
| `Bio *string` | `optional string bio = N` | pointer → optional |
| `Score *int` | `optional int64 score = N` | pointer → optional |
| `Status UserStatus` | `UserStatus status = N` | non-optional enum |
| `Status *UserStatus` | `optional UserStatus status = N` | optional enum |
| `ExpiresAt *time.Time` | `optional google.protobuf.Timestamp expires_at = N` | optional WKT |

Generated mapper — proto3 `optional` fields compile to `*T` in Go, matching domain pointers directly:

```go
// ToProto — pointer fields pass through without conversion
Bio:   d.Bio,                          // *string  → *string  (optional string)
Score: ToInt64Ptr(d.Score),            // *int     → *int64   (exported helper in pbmap)

// FromProto
Bio:   p.Bio,                          // *string  → *string
Score: FromInt64Ptr(p.Score),          // *int64   → *int
```

Note: `Optional()` without `Nillable()` in ent produces a `*string` in the domain struct (address of the zero value) — it is never nil in practice, but the proto declaration is still `optional string` to correctly represent the field semantics.

Optional enum fields require a pointer cast helper since domain and proto enum types differ:

```go
// ToProto
Status: (*entpb.UserStatus)(unsafe.Pointer(d.Status))  // or a named cast helper

// FromProto
Status: (*domain.UserStatus)(unsafe.Pointer(p.Status))
```

### Edge Mapping in Proto

All annotated edges are included in the proto message by default. Developers apply `SkipProto()` when they need to exclude an edge — for example to break a circular reference between two entities that both have `Nest()` on each other.

| Edge | Domain field | Proto field |
|---|---|---|
| Plural `IDs()` | `PostIDs []int` | `repeated int64 post_ids = N` |
| Singular `IDs()` | `OwnerID int` | `int64 owner_id = N` |
| Plural `Nest()` | `Posts PostList` | `repeated Post posts = N` |
| Singular `Nest()` | `PinnedPost Post` | `Post pinned_post = N` |
| `IDs() + Nest()` | `PostIDs []int` + `Posts PostList` | both fields in proto |
| `SkipProto()` | any | **excluded** |

**Circular reference handling.** When two entities nest each other (e.g. `User` nests `Posts` and `Post` nests `Owner User`), the developer breaks the cycle by applying `SkipProto()` on one side:

```go
// Post.owner edge — include in domain (Nest), exclude from proto to break cycle
edge.From("owner", User.Type).
    Ref("posts").
    Unique().
    Annotations(
        entdomain.Edge(entdomain.IDs(), entdomain.Nest()),
        entdomain.Field(entdomain.SkipProto()),
    )
```

The generator does not attempt to detect or resolve circular references automatically — this is left to the developer who understands their schema's intent.

### NoBulk Interaction

`WithNoBulk` suppresses `XxxList` bulk operators but does not affect proto generation. The `UserListToProto()` and `UserListFromProto()` functions are always generated in `pbmap` alongside the list type.

## Consequences

### Benefits
- Virtual fields are first-class in proto output — no silent omission
- One source of truth (ent schema + entdomain annotations) drives ent types, domain structs, proto messages, and all three mapping layers
- Field number stability via lock file — wire-compatible across schema evolution
- `UserFromProto` and `UserToProto` (in `pbmap`) eliminate the last hand-written mapping layer in gRPC adapters
- Auto-mapping for common well-known types (`time.Time`, `time.Duration`, `uuid.UUID`) with zero annotation overhead
- `GoType` fields with unknown proto types are silently excluded — no hard failure on unknown types

### Trade-offs
- Lock file must be committed and reviewed — similar discipline to database migrations
- Renaming a field creates a new field number; the old number is permanently reserved
- `GoType` virtual fields without a proto mapping (no `ProtoType(...)` and no well-known match) are silently excluded — developer must verify proto output when adding new `GoType` fields
- `Nest()` edges are included in proto by default — developers must apply `SkipProto()` to break circular references between mutually-nesting entities
- Virtual fields in `UserFromProto` are populated directly from proto; fields that require transformer logic (custom computation from ent data) will be zero in the proto→domain direction — the caller is responsible for hydrating them
- Proto generation adds a dependency on the protobuf Go runtime (`google.golang.org/protobuf`) in the generated `pbmap` package — the domain package itself remains proto-free

### Out of Scope
- gRPC service stub generation (hand-written by developers)
- Request/response wrapper types (e.g. `CreateUserRequest`)
- `buf` / `protoc` plugin integration
- Proto2 syntax
- `google.protobuf.Any` or `google.protobuf.Struct` auto-mapping
- Streaming RPC support
